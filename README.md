# Industrial Refrigeration — Process Data Analysis

**An industrial engineer analysing process data.** Two statistical studies of an industrial
air-cooling system, connecting manufacturing and process knowledge to data analysis. Both come
from real internship work, and both are reproduced here on synthetic data (see
[About the data](#about-the-data)).

The system cools moulds in a glass-container process using forced air. Cooling time — how long
each cycle must run to keep the moulds in their thermal window — is the variable of interest,
and both studies ask how process conditions move it.

Python was chosen to automate the analysis across many operating periods. The study only
becomes practical when the same procedure can be applied and compared over dozens of periods at
once, instead of working through each one by hand.

---

## What this shows at a glance

- **Study A — Humidity:** *Does air humidity affect cooling time, once temperature is accounted
  for?* A scenario-based regression analysis that controls for the dominant temperature effect
  and for the collinearity between temperature and humidity. **Finding:** a humidity signal is
  detectable only under strict conditions and cannot be confirmed with the available
  instrumentation — so the deliverable is an **instrumentation recommendation**, not an
  overstated effect.
- **Study B — Compensation tuning:** *What pressure-compensation setting keeps cooling time
  stable across temperature?* A sensitivity metric plus a parameter search. **Finding:** a clear
  optimum that flattens the cooling-time drift — a concrete, measurable improvement.

The two studies are complementary on purpose: one is a disciplined null result with a concrete
next step, the other a quantified win. Together they show both statistical restraint and
delivery.

## About the data

This work is based on a real industrial internship, so the original data is **proprietary** and
none of it appears here. Each study instead runs on a **synthetic dataset built to reproduce the
statistical structure** of the original problem — the same relationships and the same analytical
challenges — using fabricated values in a different operating range. No real operating values,
thresholds, machine identifiers, or control settings are present; every number is generated by
the code in the notebooks.

This is a deliberate choice. It keeps proprietary information fully protected while leaving the
*methodology* — the transferable part — completely intact. Building data that reproduces a
specific statistical structure (a dominant predictor collinear with a weaker one, a
sign-changing sensitivity) is also, in itself, a way to show that the mechanism is understood,
not just the tooling.

## Study A — Does humidity affect cooling time?

Temperature is the dominant driver of cooling time — by Newton's law of cooling, warmer intake
air removes heat less effectively. The open question is whether **humidity** adds a measurable
effect on top. That effect is second-order and hard to isolate, because temperature both
dominates the outcome *and* is collinear with humidity.

**Approach.** A single global regression would be dominated and confounded by temperature.
Instead, the record is split into stable operating periods, and each period is classified into
one of four scenarios: temperature strongly driving cooling time, temperature weak, and
low-collinearity windows for relative and for absolute humidity. Within each period, a family of
OLS models is compared to test whether humidity contributes *once temperature is held constant*.

**Key methods.** Relative vs. absolute humidity via the **Magnus psychrometric conversion**;
multicollinearity diagnosed with **VIF**; confounding controlled by **selecting periods on
collinearity**; significance read with appropriate caution.

**Finding.** Absolute humidity shows a small, statistically significant, *independent* effect —
but only inside the strictly selected low-collinearity windows, not in normal operation.
Relative humidity's apparent effect is largely temperature aliasing. And with the available
instrumentation — relative humidity measured away from the duct, absolute humidity *computed*
rather than measured — the effect **cannot be quantified reliably**. The conclusion is therefore
an engineering recommendation: install direct absolute-humidity sensing in the duct, piloted on
a few machines and expanded if confirmed.

[`02_scenario_analysis_humidity.ipynb`](02_scenario_analysis_humidity.ipynb).

## Study B — Tuning thermal compensation for stability

The system compensates for temperature by raising fan pressure as intake air warms. A single
constant sets how strong that response is. Too low, and cooling time still drifts up with
temperature; too high, and it overshoots and drifts down. Tuned correctly, cooling time stays
flat — the stability the compensation exists to provide.

**Approach.** Define **thermal sensitivity** as the slope of cooling time against temperature,
measured robustly on **0.5 °C conditional means** rather than raw scatter. Then sweep the
compensation constant, measure the sensitivity at each value, and find the setting that drives
it to zero.

**Finding.** The curve of sensitivity against the constant is V-shaped, with a clear minimum:
below it the system under-compensates (positive drift), above it over-compensates (negative
drift), and at the floor the temperature drift cancels out. Applying the optimum flattens the
cooling-time trend almost completely — a concrete stability improvement.

Notebook: [`03_thermal_compensation_tuning.ipynb`](03_thermal_compensation_tuning.ipynb).

## Methods & skills

**Statistics & modelling:** ordinary least squares (simple and multiple regression),
multicollinearity diagnosis via variance inflation factor (VIF), confounding controlled by
conditioning, conditional-mean (binned) regression, significance testing read with care,
parameter optimisation by search.

**Domain–data bridge:** psychrometrics (Magnus formula, relative ↔ absolute humidity),
forced-convection cooling, and translating a process-engineering question into a testable
statistical design.

**Engineering practice:** reproducible pipelines, time-series handling, synthetic-data
generation that preserves statistical structure, and responsible handling of proprietary data.

**Stack:** Python · pandas · NumPy · statsmodels · SciPy · Matplotlib · Jupyter.
